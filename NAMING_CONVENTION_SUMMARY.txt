# Migration Naming Convention - Summary

## ✅ Implementation Complete

All migration files now use a consistent, technical naming convention across three locations:

### Naming Pattern: `NNN_descriptive_name`

```
001_content_ticket_links
│
├─ File location: src/migrations/schema.js
├─ Export name:   DDL_001_CONTENT_TICKET_LINKS
└─ Enqueue call:  .enqueue('001_content_ticket_links', DDL_001_CONTENT_TICKET_LINKS)
```

## Key Features

✨ **Consistent** — Same number across file, export, and enqueue call
✨ **Ordered** — Sequential numbering (001, 002, 003...) ensures execution order
✨ **Discoverability** — All migrations visible in import statements
✨ **Scalable** — Works from 1 migration to 100+ migrations
✨ **Self-Documenting** — Descriptive name explains migration purpose

## How to Add Migration 002

### 1. Add DDL in `schema.js`
```javascript
export const DDL_002_LINK_STATUS_HISTORY = `
  CREATE TABLE IF NOT EXISTS content_ticket_link_history (
    id VARCHAR(255) PRIMARY KEY,
    link_id VARCHAR(255) NOT NULL,
    old_status VARCHAR(50),
    new_status VARCHAR(50) NOT NULL,
    changed_at BIGINT NOT NULL
  )
`;
```

### 2. Update `index.js`
```javascript
import { DDL_001_CONTENT_TICKET_LINKS, DDL_002_LINK_STATUS_HISTORY } from './schema.js';

const createDBObjects = migrationRunner
  .enqueue('001_content_ticket_links', DDL_001_CONTENT_TICKET_LINKS)
  .enqueue('002_link_status_history', DDL_002_LINK_STATUS_HISTORY);
```

### 3. Deploy
```bash
forge deploy --non-interactive -e development
forge install --non-interactive --upgrade --site <url> --product jira --environment development
```
